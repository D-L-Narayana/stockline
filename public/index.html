Place order

Stock is reserved atomically; the whole order is rejected (409 insufficient_stock) if any line is short. Send the same Idempotency-Key twice and you get the same order back (200 + Idempotent-Replayed: true).

Transfer between stores

Two ledger entries in one transaction (transfer_out + transfer_in); a 409 leaves both sides untouched. An optional Idempotency-Key makes retries safe.

Guided scenarios

Each button runs real requests against the API you are connected to and checks every step against the expected status and error code. Writes land in the demo database; the scenarios undo their own changes where they can.

1 · Oversell is rejected

Order one more unit than is on hand → 409 insufficient_stock; the balance stays unchanged.

2 · Idempotent retry

Same Idempotency-Key twice → 201 then 200 + Idempotent-Replayed: true; the same key with a different body → 422 idempotency_key_reuse.

3 · Stale version

Adjust with an expected_version one behind → 409 version_conflict; with the current version → 200.

4 · Atomic transfer

Transfer more than is on hand → 409 and both stores unchanged; a one-unit transfer succeeds (201) and is moved back.

5 · Audit

GET /integrity reports ok: true; the movement feed shows the latest ledger rows with balance_after.
